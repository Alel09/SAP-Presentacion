Problema de Aplicación

Distribución equitativa de apoyos alimentarios.

Contexto

  • Un banco de alimentos dispone semanalmente de una cantidad limitada de paquetes alimentarios para apoyar a familias de una comunidad.
  • Las solicitudes recibidas pueden superar la cantidad de apoyos disponibles. Además, las familias presentan características y necesidades diferentes, por lo que el problema no consiste únicamente en entregar los paquetes conforme se reciben las solicitudes, sino en establecer un procedimiento claro, transparente y justificable para determinar cómo distribuir los recursos disponibles.

Problema

  • Diseñar una solución algorítmica que permita procesar las solicitudes de las familias y distribuir una cantidad limitada de paquetes alimentarios de acuerdo con criterios previamente definidos.
  • El sistema deberá considerar que posiblemente no existan suficientes apoyos para todas las familias solicitantes.
Problema de Aplicación

Objetivo

  • Diseñar, formular y representar una solución algorítmica que permita realizar la asignación de los apoyos alimentarios de manera consistente con los criterios establecidos y generar información que permita evaluar los resultados obtenidos.
01
Primera parte

Patrones algorítmicos.

Problemas con historias distintas pueden compartir la misma estructura de solución. Reconocerla permite reutilizar estrategias en vez de diseñar desde cero.

02
Segunda parte

Categorización de problemas.

Antes de decidir cómo resolver un problema conviene reconocer qué tipo de problema tenemos enfrente. La categoría orienta, pero no determina por sí sola, la estrategia de solución.

03
Tercera parte

Relación entre subtareas.

Descomponer un problema no basta: también hay que entender cómo se conectan sus partes, qué información pasa entre ellas y qué subtareas dependen de otras.

04
Cuarta parte

Esquematización de la estructura del problema.

Un esquema hace visible la lógica del problema antes de programar. Sirve para comprender, comunicar y revisar la solución antes de escribir código.

05
Quinta parte

Comparación de soluciones.

Que dos algoritmos produzcan la misma salida no significa que sean equivalentes en claridad, memoria, tiempo, robustez o conveniencia para un contexto.

06
Sexta parte

Formulación de ideas precisas.

Una idea algorítmica precisa reduce ambigüedades: debe indicar qué datos se usan, qué acción se realiza, bajo qué condición y qué resultado se espera.

07
Septima parte

Diferenciación de la formulación y la implementación de la solución.

Resolver la lógica de un problema y escribirla en una herramienta concreta son etapas relacionadas, pero distintas. Una buena implementación no corrige una formulación equivocada.

Evaluación y selección de familias

Algoritmo prot_pres
	// equipo 8: KAERU NO KAMI
	Definir registro, integrantes, nmenores, ndiscapacitados, nadultos, ayudas, i, fam Como Entero
	Definir ingreso, ponderacion, promingresos, suma, promedio, ayuda, max1 Como Real
	Definir resultado Como Real
	
	Escribir "Cuantas familias se encuentran registradas:"
	Leer fam
	
	Dimensionar resultado[fam]
	
	suma <- 0
	i <- 1
	
	Mientras i <= fam Hacer
		ponderacion <- 0
		ayuda <- 0
		
		Escribir "=========================================="
		Escribir "Familia #", i
		Escribir "Bienvenido al programa de seleccion de apoyo para familias"
		Escribir "Para iniciar, ¿cuando se registro al programa? (1=sobre tiempo, 2=3 dias antes, 3=3ra semana, 4=2da semana, 5=1ra semana)"
		Leer registro
		Escribir "¿De cuanto es el ingreso mensual que tiene tu familia?"
		Leer ingreso
		Escribir "¿Cuantos integrantes tiene tu familia?"
		Leer integrantes
		Escribir "¿Cuantos integrantes menores de edad tiene tu familia?"
		Leer nmenores
		Escribir "¿Cuantos integrantes discapacitados tiene tu familia?"
		Leer ndiscapacitados
		Escribir "¿Cuantos integrantes mayores de edad tiene tu familia?"
		Leer nadultos
		Escribir "¿Cuantos apoyos tiene tu familia?"
		Leer ayudas
		
		Si integrantes <> (nmenores + nadultos + ndiscapacitados) Entonces
			ponderacion <- 1
		FinSi
		
		Si (registro = 1) O (ayudas >= 3) O (ponderacion = 1) Entonces
			resultado[i] <- 0
			Escribir "Familia descalificada o datos de integrantes inconsistentes (0 puntos)."
		SiNo
			ponderacion <- 0
			promingresos <- ingreso / integrantes
			
			Si (nmenores > 0) O (ndiscapacitados > 0) O (nadultos < 2) Entonces
				ponderacion <- promingresos / 8500
			SiNo
				ponderacion <- promingresos / 7000
			FinSi
			
			Si registro > 3 Entonces
				ayuda <- ayuda + 3
			SiNo
				ayuda <- ayuda + 1
			FinSi
			
			Si ponderacion < 2 Entonces
				ayuda <- ayuda + 3
			SiNo
				Si ponderacion < 3.5 Entonces
					ayuda <- ayuda + 2
				SiNo
					ayuda <- ayuda + 1
				FinSi
			FinSi
			
			ponderacion <- (nmenores * 100) / integrantes
			Si ponderacion < 20 Entonces
				ayuda <- ayuda + 1
			SiNo
				Si ponderacion < 35 Entonces
					ayuda <- ayuda + 2
				SiNo
					ayuda <- ayuda + 3
				FinSi
			FinSi
			
			ponderacion <- (ndiscapacitados * 100) / integrantes
			Si ponderacion < 10 Entonces
				ayuda <- ayuda + 2
			SiNo
				ayuda <- ayuda + 3
			FinSi
			
			ponderacion <- (nadultos * 100) / integrantes
			Si ponderacion <= 30 Entonces
				ayuda <- ayuda + 1
			SiNo
				ayuda <- ayuda + 3
			FinSi
			
			resultado[i] <- ayuda
		FinSi
		
		suma <- suma + resultado[i]
		i <- i + 1
	FinMientras
	
	promedio <- suma / fam
	max1 <- 0
	i <- 1
	
	Escribir "=========================================="
	Escribir "El promedio general de puntajes fue: ", promedio
	Escribir "Las familias seleccionadas (superan el promedio) son:"
	
	Mientras i <= fam Hacer
		Si resultado[i] > promedio Entonces
			Escribir "- Familia #", i, " con puntaje de: ", resultado[i]
			Si resultado[i] > max1 Entonces
				max1 <- resultado[i]
			FinSi
		FinSi
		i <- i + 1
	FinMientras
	
	Escribir "El puntaje mas alto obtenido fue: ", max1
FinAlgoritmo
